# 抽满后自动切换下一奖设计

**日期：** 2026-09-01  
**状态：** 口头设计已逐段确认；书面规格待审阅  
**范围：** 当前奖抽满后按奖品 `order` 自动切到下一个未抽完的奖；中奖屏仍公示刚抽完的奖；「开始抽奖」仅在抽奖屏且当前奖未抽满时可点。不改开奖算法、内定、数量含义、XML 名单、配奖页。

---

## 1. 背景与目标

### 1.1 现状

- 技术栈不变：Vite + React（`client/`）+ Express（`server/`）+ JSON 文件（`data/`）。
- 奖品顺序在 `prizes.json` / `catalog/prizes.json` 的 `order` 字段（不是 `participants.xml`）。
- 每个奖有 `quantity`；抽满后停稳高亮 3 秒，自动进中奖屏公示本奖全部中奖人。
- 换下一奖要主持人在控制条下拉里手动选。选未抽完的奖去奖品屏，选已抽完的奖去中奖屏。
- 「开始抽奖」在当前奖未抽满且不在滚动/停留时，在各屏都可以点（点了会进抽奖屏并滚动）。

### 1.2 已确认需求

| 维度 | 选择 |
|------|------|
| 抽满后切屏 | 仍先进中奖屏公示刚抽完的奖 |
| 下拉框何时改成下一奖 | 抽满那一次开奖成功后立刻改（方案 A） |
| 下一奖怎么找 | 按 `order` 往后找第一个未抽完的奖；已抽完的跳过；后面没有则不换奖、不循环（方案 A） |
| 谁改 `currentPrizeId` | 服务端在抽满的那次 `POST /api/draw` 里改（方案 1） |
| 中奖屏上开始抽奖 | 禁用；主持人切到抽奖屏再开下一奖 |
| 开始抽奖可点条件 | 仅抽奖屏 + 已选当前奖 + 该奖未抽满 + 不在滚动/再滚/3 秒停留 |

### 1.3 目标

- 一个奖抽满后，不必再点下拉框；切到抽奖屏即可看到下一奖并继续抽。
- 观众仍先看到刚抽完这一奖的中奖公示。
- 全部奖抽完后，「开始抽奖」保持置灰，文案「已抽取」。

### 1.4 非目标

- 抽满后跳过中奖屏、或自动开始下一奖滚动。
- 抽满后从头循环未抽完的奖。
- 手动选中已抽完的奖时再次自动往后跳。
- 新增 session 字段或新的 JSON 文件。
- 改内定、不可重复中奖、数量含义、点停开奖、3 秒停留时长。
- 改 XML 名单、配奖页、管理页、音效、公网部署。

## 2. 整体流程

四屏顺序不变：参与 → 奖品 → 抽奖 → 中奖。

同一奖（数量 N）前 N−1 次不变：停稳高亮 3 秒，留在抽奖屏，可再点「开始抽奖」抽同一奖。

第 N 次点停后：

1. 后台写入中奖记录；若该奖因此抽满，立刻把 `currentPrizeId` 改成后面第一个未抽完的奖。没有下一个则保持刚抽完的这一奖。
2. 抽奖屏照常停稳、高亮约 3 秒。控制条下拉框此时已是下一奖（若有）。
3. 3 秒结束自动进入中奖屏，公示**刚抽完这一奖**的全部中奖人（不跟下拉框走）。
4. 中奖屏上「开始抽奖」禁用。主持人点「抽奖」后，大屏为新奖的名称/图片，下拉框不用再改。再点「开始抽奖」开下一奖。点「奖品」同样看到新奖，但该屏不能开抽。
5. 全部奖都抽完：停在最后一奖的中奖屏，下拉框仍是它，按钮为「已抽取」。

手动用下拉框选奖的行为不变：未抽完去奖品屏，已抽完去中奖屏。不会因为选中一个已抽完的奖就再次自动往后跳。

滚动、再滚或 3 秒停留期间主持人手动切屏：取消尚未执行的自动跳转（含未启动或进行中的 3 秒定时器）。若已点停，中奖记录和（若已抽满）当前奖切换都已持久化，只是不自动进中奖屏。

---

## 3. 数据模型

不新增文件，不给 session 加字段。剩余次数仍由该奖 `winners` 条数与 `quantity` 比较得出。

### 3.1 当前奖与刚抽完的奖

- **当前奖** `session.currentPrizeId`：下拉框、奖品屏、抽奖屏、下一次开奖都认它。抽满且后面还有未抽完的奖时，由抽满那一次开奖改成下一奖。
- **刚抽完的奖**仍用现有 `lastWinnerPrizeId`（本条开奖写入的 `prizeId`，即刚抽出的那一奖，不是换完后的当前奖）。

### 3.2 中奖屏展示哪一奖

纯函数，不另存 ID：

- 当前奖已经抽完 → 显示当前奖（手动点开已抽完的奖、全部抽完停在最后一奖）。
- 当前奖还没抽完，且 `lastWinnerPrizeId` 有值 → 显示 `lastWinnerPrizeId`（抽满自动进中奖屏时，下拉框已是下一奖，画面仍是刚抽完的那一奖）。
- 否则 → 显示当前奖。

中奖屏上方名单按这个展示奖的 `prizeId` 过滤 `winners`，不用换完后的 `currentPrizeId` 去滤刚抽完的人。

### 3.3 下一奖

纯函数 `nextIncompletePrizeId(prizes, winners, currentPrizeId)`：

1. 奖品按 `order` 升序。
2. 找到当前奖下标；找不到则返回 `null`（不换奖）。
3. 从下一项起向后扫描，返回第一个「中奖条数 < quantity」的奖的 `id`。
4. 扫到末尾都没有则返回 `null`。不从头循环。

`quantity` 缺省按 1，与现有 `prizeQuantity` 一致。

## 4. 「开始抽奖」按钮

同一物理按钮，四种文案：滚动等待点停时为「停」；减速/再滚/3 秒停留时为禁用的「抽奖中…」；当前奖已抽满（含全部奖抽完停在最后一奖）为禁用的「已抽取」；其余为「开始抽奖」。

「开始抽奖」可点，必须同时满足：

- 当前视觉屏幕是抽奖屏（参与 / 奖品 / 中奖屏都不可点开始）。
- 已选当前奖，且这一奖还没抽满（数量为 3 时，第 2、第 3 次仍可点）。
- 不在滚动、点停后再滚、3 秒停留里。

置灰：不在抽奖屏；没选奖；当前奖已抽满；所有奖都抽完；抽奖进行中。

「停」仅在抽奖屏滚动且尚未点停时可点，规则与现在相同。

前端在抽奖屏以外点到开始（或快捷键等）必须忽略，不进入滚动。

## 5. 接口

### 5.1 `POST /api/draw`

开奖、内定槽、资格、错误消息与现在相同。读取请求开始时的 `session.currentPrizeId` 作为本抽奖品，不因换奖而抽错奖。

写入中奖记录、更新 `lastWinnerParticipantId` / `lastWinnerPrizeId`（值为**本抽**的奖与人）之后：若本奖因此抽满，调用 `nextIncompletePrizeId`；非 `null` 则写入 `session.currentPrizeId`。未抽满、找不到下一奖、当前奖不在列表中：都不改 `currentPrizeId`。

返回值在现有字段上增加 `currentPrizeId`（本响应写完 session 后的当前奖；没有下一奖时仍是刚抽完的奖）。`prizeComplete` 仍表示**刚刚抽的那一奖**是否抽满，不表示下一奖是否可抽。

`publicScreen` 在本次响应里仍保持 `"draw"`，以便前端播完停稳与 3 秒停留。

### 5.2 保持不变

`GET /api/public/view`、`PUT /api/session/current-prize`、`PATCH /api/session` 的字段形状不改。中奖屏用 view 里已有的 `session.currentPrizeId`、`lastWinnerPrizeId`、`winners`、`prizes` 按 3.2 计算展示奖。手动换奖接口不自动跳到「下一未抽完奖」。

## 6. 组件改动（最小集合）

| 位置 | 改动 |
|------|------|
| `server` 领域函数 | `nextIncompletePrizeId`；中奖屏展示奖也可抽成纯函数供前后端/测试共用或前端自写等价逻辑 |
| `POST /api/draw` | 抽满后改 `currentPrizeId`；返回增加 `currentPrizeId` |
| `HostControlBar` | 「开始抽奖」仅抽奖屏且未抽满可点；已抽满为「已抽取」 |
| `PublicStage` / `drawFlow` | 3 秒后仍按 `prizeComplete` 进中奖屏；中奖屏展示奖按 3.2；非抽奖屏不启动滚动 |
| `WinnerScreen` 数据源 | 按展示奖过滤本奖中奖人，不用换完后的 `currentPrizeId` 误滤成空名单 |
| 前端 `DrawResult` 类型 | 增加 `currentPrizeId` |
| README | 抽满后自动切下一奖；开始按钮仅抽奖屏可点 |

不改：`resolveWinner`、`listEligible`、内定槽、数量校验、姓名 XML、配奖、四屏枚举。

## 7. 错误处理

| 情况 | 行为 |
|------|------|
| 抽满后没有未抽完的下一奖 | 不改 `currentPrizeId`，不报错，按钮「已抽取」 |
| 本抽未抽满 | 不换奖 |
| 当前奖不在奖品列表 | 不换奖；开奖本身按现有「当前奖品不存在」处理 |
| 点停失败 | 不写中奖、不换奖，可再开始 |
| 滚动中未点停就切屏或刷新 | 不写中奖、不换奖 |
| 已点停后、停留中手动切屏 | 中奖与（若抽满）换奖已写入；取消自动进中奖屏 |
| 非抽奖屏触发开始 | 忽略，不滚动 |
| 抽奖屏但当前奖已抽满 / 无当前奖 / `canDraw === false` | 与现在相同：不滚动，对应中文提示 |

## 8. 测试

**后端：** 三个奖 order 0/1/2。抽满第一个后 `currentPrizeId` 为第二个，`prizeComplete` 为 true，返回的 `currentPrizeId` 为第二个，`lastWinnerPrizeId` 仍为第一个。第二个事先抽满则跳到第三个。最后一个抽满不改 ID。未抽满不换奖。当前奖不在列表不换奖（开奖失败路径仍按现有）。

**前端：** 抽满停留结束后进中奖屏，名单是刚抽完的奖；下拉框是下一奖。中奖屏、奖品屏、参与屏上开始按钮禁用。切到抽奖屏后可见下一奖且可点开始。同一奖数量 3 时，抽奖屏上前两次停留后仍可点开始。全部抽完时按钮为「已抽取」。3 秒用假计时器。

**手工：** 按目录顺序抽：第一奖抽满 → 中奖屏公示第一奖、下拉框已是第二奖 → 点「抽奖」看到第二奖 → 点开始继续。跳过已抽完的中间奖。最后一个抽完后开始按钮保持置灰。

**不测：** 多窗口逐帧对齐、音效、改 XML/配奖。

## 9. 验收标准

- [ ] 当前奖抽满后，`currentPrizeId` 变为按 `order` 的下一个未抽完奖；下拉框立刻显示该奖。
- [ ] 自动进入的中奖屏公示刚抽完那一奖的全部中奖人，即使下拉框已是下一奖。
- [ ] 没有下一个未抽完的奖时不换奖；按钮为「已抽取」。
- [ ] 中间已抽完的奖被跳过；不循环回前面的未抽完奖。
- [ ] 手动从下拉框选已抽完的奖仍只进该奖中奖屏，不会再次自动往后跳。
- [ ] 「开始抽奖」仅在抽奖屏且当前奖未抽满、未在抽奖过程中时可点；参与/奖品/中奖屏置灰。
- [ ] 同一奖未抽满时，抽奖屏上可连抽剩余次数。
- [ ] 点停开奖、3 秒停留、未满留在抽奖屏、内定与不可重复中奖行为不变。
- [ ] README 与上述现场操作一致。
