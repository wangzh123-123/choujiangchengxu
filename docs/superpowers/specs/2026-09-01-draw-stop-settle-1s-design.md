# 点停后 1 秒内停到中奖人设计

**日期：** 2026-09-01  
**状态：** 口头设计已逐段确认；书面规格待审阅  
**范围：** 缩短点「停」之后名字再滚到中奖人的时间，并把滚动一格的间隔加快。不改开奖规则、3 秒停留、四屏流程。

---

## 1. 背景与目标

### 1.1 现状

- 点「开始抽奖」只滚动，点「停」才 `POST /api/draw`，由后台抽出中奖人。
- 拿到中奖人后，抽奖屏名字仍按 **80ms 一格**继续滚动，再固定滚 **2800ms** 才停到该人并高亮。
- 停稳高亮后再停留 **3000ms**（未抽满留在抽奖屏，抽满进中奖屏）。
- 滚动组件：`client/src/components/NameTicker.tsx`（`ROLL_MS = 2800`，`setInterval` 间隔 80ms）。

主持人点停后仍会感觉「循环好几秒才定人」。中奖人在点停时已经由后台决定，慢的是这段再滚动画。

### 1.2 已确认需求

| 维度 | 选择 |
|------|------|
| 点停后定人观感 | 1 秒内停到中奖人并高亮（方案 A） |
| 停稳后停留 | 仍为 3000ms，行为与现在相同 |
| 实现策略 | 只缩短再滚时长，不做真实减速、不立刻定格（方案 1） |
| 滚动一格间隔 | 全程 40ms（含点停前自由滚、点停后再滚） |
| 谁决定中奖人 | 仍是后台；不采用「停在当时屏幕上的名字」 |

### 1.3 目标

- 本地正常开奖时，从点「停」到中奖人高亮，落在 **1 秒内**。
- 滚动更快（40ms 一格），现场仍能看出在滚名字。
- 开奖时机、内定、数量连抽、3 秒停留、切屏规则保持不变。

### 1.4 非目标

- 真实减速算法（越滚越慢）。
- 接口一返回就立刻定格、取消再滚。
- 缩短或取消停稳后的 3000ms 停留。
- 改后端开奖、内定、不可重复中奖、奖品数量。
- 改控制条文案含义、四屏顺序、姓名录入、管理页。
- 多设备逐帧对齐、音效、公网部署。

---

## 2. 时间线

一次抽取：

1. 点「开始抽奖」：进入抽奖屏，名字按 **40ms 一格**滚动。此时不写中奖记录。
2. 点「停」：立刻 `POST /api/draw`。中奖人由服务端决定（内定槽或随机可抽池），与当时屏幕上的名字无关。
3. 接口成功并得到中奖姓名后，名字最多再滚 **800ms**，然后停到该人并高亮。
4. 高亮后再停留 **3000ms**（不含第 3 步的 800ms）。未抽满：留在抽奖屏，主按钮恢复「开始抽奖」。抽满：自动进入中奖屏。

800ms 从「前端已拿到中奖姓名」起算，不是从按下「停」起算，以便给本地接口留余量。本地接口通常几十毫秒，点停到高亮一般落在 1 秒内。接口变慢时：返回后仍只再滚 800ms，不再使用 2800ms。

点停后到高亮这段（再滚 800ms）以及随后的 3000ms 停留期间，主按钮仍为禁用的「抽奖中…」，不可再点开始或停。只是再滚从约 2.8 秒变成约 0.8 秒。

## 3. 组件改动（最小集合）

改两个文件：

| 位置 | 改动 |
|------|------|
| `client/src/components/NameTicker.tsx` | 再滚时长 `ROLL_MS`：2800 → **800**；滚动间隔导出为 `TICK_MS`：80 → **40**。两个常量都 `export`，供测试断言。 |
| `README.md` | 现场步骤里「开奖并减速停名」改为一句：点停后约 1 秒内停到中奖人并高亮，再停留约 3 秒。 |

停稳方式不变：到时用现有 `pickSettleIndex` 跳到中奖姓名所在格，进入 `settled` 高亮，再回调 `onSettled`，由现有 `startSettleHold` 做 3000ms 停留。

不改：`PublicStage` 开奖时序、`settleHold.ts` 的 3000ms、后端路由、管理页。

---

## 4. 数据流与错误处理

数据流与现在相同：

```
开始 → 滚动快照（40ms/格）→ 停 → POST /api/draw → 姓名再滚 800ms → 停稳高亮 → 停留 3000ms → 按是否抽满切屏
```

| 情况 | 行为 |
|------|------|
| 点停时开奖失败 | 立刻停滚、提示错误、不计数，可再点「开始抽奖」 |
| 再滚 800ms 或 3000ms 停留中再点开始或停 | 忽略 |
| 未点停就切屏或刷新 | 不写中奖记录 |
| 已点停后手动切屏 | 中奖记录已持久化；取消尚未执行的自动跳转 |
| 接口慢 | 返回后仍再滚 800ms；不把总时长垫回 1 秒，也不回到 2800ms |

---

## 5. 测试

**前端：**

- 断言导出常量：`ROLL_MS === 800`、`TICK_MS === 40`。
- 组件测试：拿到 `settleName` 后，推进 800ms 才进入停稳并触发 `onSettled`；799ms 时仍未停稳。
- 现有 3000ms 停留用例保持：`SETTLE_HOLD_MS === 3000`；未抽满不进中奖屏，抽满才进。
- 点开始仍不请求 `/api/draw`；点停才请求。

**不测：** 真实墙钟是否严格小于 1000ms（含网络）、多浏览器对齐、音效。

**手工：** 大屏开始滚动，确认翻名更快；点停后约 1 秒内高亮中奖人；再等 3 秒，未抽满可再抽。
