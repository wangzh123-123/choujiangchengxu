# 姓名录入与四屏顺序调整设计

**日期：** 2026-08-24  
**状态：** 口头设计已逐段确认；书面规格待审阅  
**范围：** 将大屏「假二维码参与」改为逐个输入姓名；调整四屏顺序；抽奖停稳选中停留 3 秒后进入中奖屏；中奖屏增加已中奖名单。

---

## 1. 背景与目标

### 1.1 现状

- 技术栈不变：Vite + React（`client/`）+ Express（`server/`）+ JSON 文件（`data/`）。
- 对外四屏当前顺序：奖品 → 参与（假二维码 + 用户 ID + 姓名）→ 抽奖滚动 → 中奖公示（仅本轮一人）。
- 添加参与者接口要求客户端同时提供 `id` 与 `name`；重名精确匹配拒绝。
- 抽奖滚动停稳后立即切到中奖屏。
- `/admin` 维护奖品与按奖品硬内定；主持人控制条切屏、选奖、开抽，可隐藏。

### 1.2 已确认需求

| 维度 | 选择 |
|------|------|
| 录入方式 | 第一屏逐个输入姓名；内部自动生成 ID |
| 第一屏编辑 | 始终显示输入框；名单可改名、可删除 |
| 四屏顺序 | 参与 → 奖品 → 抽奖 → 中奖 |
| 抽奖停靠 | 停稳并选中中奖人后停留 3 秒，再自动切第四屏 |
| 第四屏 | 本轮中奖人大字公示 + 下方已中奖名单 |
| 实现策略 | 在现有四屏与 API 上做最小改动（方案 1） |

### 1.3 目标

- 活动前主持人在第一屏把参与者姓名录完；观众能看到名单增长。
- 现场展示顺序符合「先人、再奖、再抽、再公示」。
- 开奖过程有明确的「选中」停顿，再进入公示。
- 第四屏既能突出本轮中奖人，也能回顾已开奖结果。

### 1.4 非目标

- 真实扫码、微信登录、批量粘贴导入。
- 把名单录入搬到 `/admin`（admin 仍只管奖品与内定）。
- 用姓名取代内部 `id`（内定与中奖记录继续绑 `participantId`）。
- 抽奖停靠的服务端状态机、多设备逐帧对齐。
- 音效、粒子、主题皮肤。
- 公网部署（见 `2026-08-23-lottery-public-deploy-design.md`）。

## 2. 整体流程

四屏仍一次只显示一屏，切屏淡入淡出。主持人控制条顺序与快捷按钮改为：

1. **参与**（`enroll`）
2. **奖品**（`prize`）
3. **抽奖**（`draw`）
4. **中奖**（`winner`）

现场路径：

1. 在参与屏逐个录入（可改名、删除）。
2. 切到奖品屏给观众看当前奖品。
3. 点「开始抽奖」：自动进入抽奖屏，滚动加减速，停稳后高亮选中中奖人，停留 3 秒。
4. 3 秒到后自动进入中奖屏。
5. 换下一个奖品，从奖品屏再抽。

控制条仍可手动切屏、选择当前奖品、隐藏/显示。滚动或 3 秒停留期间「开始抽奖」不可用。若在滚动或停留期间主持人手动切到其他屏，则取消自动跳转到中奖屏，停在其选择的那一屏。

代码与仓库种子里，新 session 的 `publicScreen` 默认为 `enroll`。已部署环境里已经写下的 `session.json` 按其中保存的屏恢复，发版时不改写该文件。

`/admin` 路由、口令、奖品配置、硬内定规则、同一人不可重复中奖、轻量动效限制（无音效/粒子）均保持不变。假二维码从大屏移除。

## 3. 第一屏：参与人员

### 3.1 界面

- 标题为「参与人员」。无二维码、无用户 ID 输入。
- 上方：单个姓名输入框 + 「添加」按钮。
- 下方：已录入名单，每行可改名、可删除。
- 控制条隐藏后，输入框与改删控件仍然显示。

### 3.2 添加

- 提交前去掉首尾空白；空字符串拒绝。
- 只把 `name` 发给后端；`id` 由服务端生成 UUID，界面永不展示。
- 成功后清空输入框，名单立即出现新行。
- 与已有名字完全相同（trim 后精确匹配）则不创建，提示「名称重复，请重新输入」。

### 3.3 改名

- 行内编辑，回车或失焦保存。
- trim 后为空则拒绝，恢复原名并提示。
- 改成自己的原名视为成功（不报错）。
- 改成其他已存在名字则拒绝，提示「名称重复，请重新输入」。
- 已中奖的人允许改名；第四屏与已中奖名单显示新名字。中奖记录仍引用同一 `participantId`，不改写 `winners.json` 的人 id。

### 3.4 删除

- 未中奖：删除该参与者，立即离开名单与抽奖池。若 `/admin` 将其设为某奖内定，清除对应内定。
- 已中奖：不允许删除。该行删除按钮禁用；若仍请求接口则失败并提示「已中奖用户不能删除」。
- 清空全部参与者仍只在 `/admin`，需管理口令，行为与现在相同。

### 3.5 与抽奖的关系

- 抽过若干奖后仍可回到第一屏加人。
- 已中奖的人留在名单中（可改名、不可删），但不进入后续抽奖池（沿用现有资格规则）。
- 「开始抽奖」时对当时名单做名字快照用于本轮滚动。滚动或 3 秒停留期间的增删改不影响本轮滚动内容。

## 4. 第三屏停靠与第四屏公示

### 4.1 抽奖滚动与选中

- 点「开始抽奖」后的校验与现在相同：无当前奖品、该奖已抽、没有可抽用户时不进入滚动，并给出已有提示。
- 进入抽奖屏后滚动加减速；**停稳之后**才进入选中态：滚动冻结，中奖人高亮（放大或描边即可）。
- 从选中这一刻起停留 **3000ms**。这 3 秒不含减速过程。
- 停留期间会话仍为抽奖屏（`publicScreen: "draw"`），避免其他打开同一 URL 的页面在 3 秒未到时先看到中奖屏。
- 3000ms 到点后，再把会话切到中奖屏。
- 滚动或停留期间若主持人手动切屏：取消尚未执行的自动跳转（含尚未启动或已在走的 3 秒定时器）；若滚动尚未停稳，忽略随后的停稳回调，不再自动进中奖屏。

### 4.2 中奖屏

- 上方保持现有公示：本轮中奖人姓名（大字高亮）+「获得 {奖品名}」+ 奖品图。
- 下方增加已中奖名单：按开奖顺序（`winners` 数组顺序）列出截至目前全部记录，**含本轮**。每行格式：`奖品名 — 中奖人`。
- 换奖再抽后，上方换成新的本轮中奖人，下方名单变长。
- 控制条中已抽奖品仍标「已抽」，不可再抽。

奖品屏本身不改交互，只是从第二位变为第二屏。

## 5. 接口与数据

存储仍是 `data/participants.json` 等现有 JSON，不新增文件类型。

### 5.1 `POST /api/participants`

- 请求体以 `name` 为准（字符串，trim 后非空）。
- 服务端始终生成新的 UUID 作为 `id`。请求里即使带 `id` 也忽略。
- 重名：`409`，消息「名称重复，请重新输入」。
- 空名：`400`。
- 成功：`201`，返回 `{ id, name }`。
- 鉴权：与现在相同，不要求管理口令。

### 5.2 `PATCH /api/participants/:id`（新增）

- 请求体 `{ name }`。trim 后非空。
- 目标不存在：`404`。
- 改成他人已有名：`409`，消息「名称重复，请重新输入」。
- 改成自己原名：`200`，原样返回。
- 已中奖用户允许改名。
- 鉴权：与添加相同，不要求管理口令。

### 5.3 `DELETE /api/participants/:id`（新增）

- 目标不存在：`404`。
- 该 `id` 已出现在 `winners` 中：`409`，消息「已中奖用户不能删除」。
- 否则删除该参与者；所有指向该 `id` 的内定一并删除。
- 成功：`204`。
- 鉴权：与添加相同，不要求管理口令。

### 5.4 保持不变

- `GET /api/participants`
- 管理口令下的 `DELETE /api/participants`（清空全部 + 清全部内定）
- 奖品、会话、开奖、内定、`GET /api/public/view`
- 第四屏名单由现有 `public/view` 的 `winners` + `prizes`/`currentPrize` + `participants` 在前端拼接，不新开列表接口

内部身份始终是 `id`。改名只改 `participants` 里的 `name`。

## 6. 组件改动（最小集合）

| 位置 | 改动 |
|------|------|
| `HostControlBar` | 屏顺序改为 `enroll, prize, draw, winner`；标签仍为 参与 / 奖品 / 抽奖 / 中奖 |
| `EnrollScreen` | 去掉二维码与 ID；姓名添加 + 名单改删 |
| `PublicStage` | 停稳后 3 秒再 `goScreen("winner")`；中途切屏取消定时器；把中奖列表数据传给中奖屏 |
| `DrawScreen` / 滚动条 | 停稳后保持选中高亮至切屏 |
| `WinnerScreen` | 增加已中奖名单区域 |
| `session` 默认值 | 新 session 的 `publicScreen` 默认为 `enroll` |
| 前端 API 封装 | `addParticipant(name)`；新增 `patchParticipant`、`deleteParticipant` |
| `server` 参与者路由 | POST 忽略客户端 id；新增 PATCH、按 id 的 DELETE |
| README | 现场流程、假二维码说明改为姓名录入与新屏序 |

不改抽奖核心算法、内定必中规则、资格过滤（已中奖者不再可抽）。

## 7. 错误处理

| 情况 | 行为 |
|------|------|
| 空姓名（添加或改名） | 不保存；表单或行内提示 |
| 重名 | 不保存；「名称重复，请重新输入」 |
| 删除已中奖者 | 按钮禁用；接口 409 |
| 删除/改名目标不存在 | 404；刷新名单 |
| 保存/网络失败 | 显示错误，界面不假装成功 |
| 无人可抽 / 奖品已抽 | 不进入滚动，沿用现有 toast |
| 滚动或 3 秒停留中再点开抽 | 按钮禁用，忽略 |

## 8. 测试

**后端：** 只发姓名即可添加并得到 `id`；空名、重名失败。改名成功；改成他人名失败；改成原名成功；已中奖者可改名。删除未中奖成功并清掉该人内定；删除已中奖失败。原有开奖、不可重复中奖、清空全部仍通过。

**前端：** 控制条顺序为参与 → 奖品 → 抽奖 → 中奖。参与屏无二维码、无 ID 框，能添加/改名/删除。中奖屏能渲染本轮中奖人 + 已中奖名单。3 秒停留用假计时器断言（不等真实动画）。

**手工：** 录几人（含改名、删除）→ 奖品屏 → 抽一次，确认停稳选中满 3 秒再进第四屏 → 再抽一次，确认名单变长。

**不测：** 真扫码、音效、多浏览器同一帧对齐、公网部署。

## 9. 验收标准

- [ ] 大屏第一屏为姓名录入与名单，无假二维码、无用户 ID 框。
- [ ] 可逐个添加、行内改名、删除未中奖者；已中奖者可改名不可删除。
- [ ] 控制条与上一屏/下一屏顺序为参与 → 奖品 → 抽奖 → 中奖。
- [ ] 开抽后滚动停稳并高亮中奖人，停留 3 秒后自动到中奖屏。
- [ ] 停留期间手动切屏不会再自动跳到中奖屏。
- [ ] 中奖屏上方为本轮中奖人与奖品，下方为含本轮在内的已中奖名单。
- [ ] 重名拒绝；内部仍用 UUID `id` 绑定内定与中奖。
- [ ] `/admin` 内定与不可重复中奖行为不变。
- [ ] README 现场流程与上述行为一致。
