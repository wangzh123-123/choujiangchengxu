# 抽奖验证测试模块设计

**日期：** 2026-08-24  
**状态：** 口头设计已逐段确认；书面规格待审阅  
**范围：** 新增服务端自动化测试，用 100 个不重名参与者验证开奖、硬内定、改名与删除等边界。不改产品逻辑。

---

## 1. 背景与目标

### 1.1 现状

- 技术栈不变：Express（`server/`）+ Vitest + supertest；数据为 JSON 文件。
- 已有服务端测试覆盖健康检查、参与者加改删、少量开奖与内定（多为 2～3 人）。
- 开奖：无内定时在可抽池中均匀随机；有内定时 `resolveWinner` 直接返回内定 `participantId`。
- 内定优先级最高：已中奖者仍可被设为另一奖内定并再中（当前实现；与 `hard-preset-draw` 规格中「已中奖不可再内定」不一致。本模块按**当前代码**锁断言）。
- 参与者：`POST` 只收 `name`；`PATCH` 改名；`DELETE /:id` 单人删除；已中奖不可删；删除未中奖者时清除指向该人的内定。

### 1.2 已确认需求

| 维度 | 选择 |
|------|------|
| 形态 | 仅 Vitest 自动化测试（方案 A），无应用内造数按钮 |
| 抽奖验证 | 功能场景，不测统计均匀 |
| 测试层 | 只测服务端 HTTP API，不测前端、不加 Playwright |
| 内定与已中奖 | 按当前代码：已中奖者可再被内定并再中 |
| 组织 | 一个场景测试文件 + 造名辅助，现有测试保留 |
| 产品代码 | 本轮不改 `draw` / `presets` / 参与者路由 |

### 1.3 目标

- 用固定规模（100 人）验证：无内定开奖结果合法、有内定必中、中奖后资格变化、奖品不可重复开。
- 在同一规模下验证添加、改名、重名、删除及与内定/中奖记录的交叉。
- 用例隔离；有内定的结果确定，无内定只断言「中奖人合法」故不因随机而抖动。`npm run test --prefix server` 即可跑。

### 1.4 非目标

- 前端组件、浏览器端到端、抽奖滚动动画、停稳 3 秒停留。
- 中奖次数是否均匀、卡方一类统计检验。
- 公网部署、真扫码、并发双开奖。
- 管理页全量回归（清空全部参与者点到即可）。
- 修改开奖或内定产品行为去对齐 `hard-preset-draw` 规格。
- 新增 npm 依赖。

## 2. 整体结构

新增：

| 文件 | 职责 |
|------|------|
| `server/tests/lottery.verification.test.ts` | 验证模块全部用例 |
| `server/tests/helpers/hundredNames.ts` | 生成正好 100 个互不重复的姓名 |

造名不使用真随机中文名，避免偶发碰撞。辅助函数返回 `用户001` … `用户100`（三位数字补零）。调用方循环 `POST /api/participants`。

每个 `it` 使用临时数据目录（与 `participants.mutate.test.ts` 相同模式）：`mkdtemp` + 写入 `config.json` + `LOTTERY_DATA_DIR`，**不读写**仓库 `data/*.json`。`afterEach` 清理环境变量与管理会话。

现有测试文件全部保留。不改 `server/src` 下产品代码。不改客户端。

跑法：`npm run test --prefix server`。需要内定时走 `POST /api/admin/login`；添加/改名/单人删除不要求口令。

公共步骤抽成测试文件内辅助函数，避免复制粘贴：

- `makeApp()`：临时目录 + `createApp`
- `login(app)`：返回管理 token
- `seed100(app)`：写入 100 人，返回 `{ id, name }[]`
- `putPrize(app, token, prize)`：写入奖品并可选设为当前奖

失败断言用长度、id 集合、单条 `name`/`participantId` 对比，不把 100 人整表放进 `expect`。

## 3. 抽奖与内定

除「无人可抽」外，开奖/内定相关用例先 `seed100`，再布置奖品与当前奖品。

### 3.1 无内定开奖

- `POST /api/draw` 返回 `200`。
- `participantId` 与 `name` 属于这 100 人，且开奖前属于可抽池。
- `GET /api/winners` 增加一条，`prizeId` 与当前奖一致。
- 该人不再出现在 `GET /api/eligible`；其余 99 人仍可抽。
- 同一奖品再次 `POST /api/draw` 失败（该奖已开奖），状态码 `400`，消息与现实现一致（「该奖品已开奖」）。

### 3.2 有内定开奖

- 在 100 人中指定一人（例如 `用户050`），管理口令下 `PUT /api/presets/:prizeId`。
- 开奖结果必须是该内定人，不得抽到池中其他人。
- 按当前实现：该人已中过其他奖，仍可被设为另一奖内定并再中；本模块锁这条行为。

### 3.3 其它开奖边界

- 未选择当前奖品 → `400`，「未选择当前奖品，无法开奖」。
- 先把当前奖设为 `p1`，再 `PUT /api/prizes` 去掉 `p1`，然后开奖 → `400`，「当前奖品不存在」。
- 无内定且可抽池为空（不造 100 人，空名单或清空后）→ `400`，「没有可抽奖用户」。
- 内定的奖品不存在 → `404`，「奖品不存在」；用户不存在 → `404`，「用户不存在」。
- `DELETE /api/presets/:prizeId` 取消内定后开奖：中奖人必须是当时可抽池中的人。

不测随机分布，不注入 `Math.random`（走真实 `POST /api/draw`）。无内定用例只断言「结果合法」，不断言具体是哪一个人。

## 4. 名单边界（100 人池）

规则按当前参与者 API。与 `participants.mutate.test.ts` 并存，本模块在 100 人规模上重放关键路径并覆盖与开奖/内定的交叉。

### 4.1 添加

- 空字符串或纯空格 → `400`，名单长度仍为 100。
- 再添加已有名（如 `用户001`）→ `409`，消息为「名称重复，请重新输入」。
- 添加新名（如 `用户101`）→ `201`，名单长度为 101。

### 4.2 改名（`PATCH /api/participants/:id`）

- `用户001` 改为 `用户001改` → `200`，`id` 不变，列表中旧名消失、新名出现。
- 改成自己当前名 → `200`。
- 改成池中他人名 → `409`，原名不变。
- 不存在的 id → `404`。
- 空名或纯空格 → `400`。
- 已中奖者允许改名；`GET /api/public/view` 中该中奖人显示新名；`winners` 记录仍引用同一 `participantId`。
- 先内定再改名：开奖仍中该 `id`，响应里的 `name` 为新名。

### 4.3 删除（`DELETE /api/participants/:id`）

- 未中奖者 → `204`，名单少 1，不再出现在可抽池。
- 若该人是某奖内定：删除后该奖内定被清除；再开奖不得中这个已删除 id。
- 已中奖者 → `409`，「已中奖用户不能删除」，该人仍在名单中。
- 不存在的 id → `404`。
- 管理口令下 `DELETE /api/participants`（无 id）：名单空、内定空。不在此模块展开其它管理接口。

## 5. 用例组织

一个顶层 `describe("lottery verification")`，子块：

1. 造 100 人
2. 无内定开奖
3. 有内定开奖
4. 名单添加 / 改名 / 删除

每个 `it` 独立搭环境、独立造数，互不依赖顺序。

---

## 6. 错误处理（测试侧）

| 情况 | 断言 |
|------|------|
| 业务拒绝（空名、重名、已抽、无人可抽等） | HTTP 状态码 + 现有中文 `message` |
| 造人过程中某次 `POST` 非 201 | 该用例失败，不继续开奖 |
| 临时目录或 app 创建失败 | Vitest 报错，视为环境问题 |

产品 API 的错误文案本轮不改；测试与当前字符串对齐。

## 7. 验收标准

- [ ] 存在 `server/tests/lottery.verification.test.ts` 与 100 人姓名辅助。
- [ ] 可一次造齐 100 个不重名参与者。
- [ ] 无内定：中奖人在可抽池；中完后移出可抽池；该奖不能再抽。
- [ ] 有内定：100 人池中指定人必中；已中奖者仍可被内定并再中（锁当前实现）。
- [ ] 改名、重名、空名、删未中奖、删已中奖、删内定人的行为与第 3、4 节一致。
- [ ] `npm run test --prefix server` 全绿；原有服务端测试仍通过。
- [ ] 未修改 `server/src` 产品逻辑，未新增运行时依赖。

若日后产品改为「已中奖不可再内定」，须同步改本模块第 3.2 节与对应断言，不能只改测试让它变绿。
