# 变更提案

## 背景（Why）

现场抽奖需要一套可本地运行的展示系统：对外给参与者看奖品、参与、抽奖过程与中奖结果，对内由主持人配置奖品、录入用户并硬内定中奖人。当前仓库为空项目，缺少该能力，导致活动只能依赖临时表格或不透明的手工流程。

## 变更内容（What Changes）

- 新增本地「前端 + 小后端」抽奖展示应用（Vite + React + Express + JSON 持久化）。
- 新增对外四屏：奖品展示、假二维码参与（可手动添加用户）、抽奖滚动、中奖展示。
- 新增对内 `/admin` 口令页：维护奖品列表、按奖品硬内定中奖人。
- 新增主持人控制条：切屏、选择当前奖品、开始抽奖（可隐藏）。
- 抽奖规则：有内定则必中（滚动为表演）；无内定则随机；同一人不可重复中奖；添加用户时名称重复须提示并拒绝。
- 轻量动效：切屏淡入淡出、滚动加减速停靠、中奖高亮。

## 能力（Capabilities）

### 新增能力

- `prize-catalog`：本地配置多奖品（名称、图片）并选择当前抽奖奖品。
- `participant-enrollment`：手动添加抽奖用户（id + 名称），重名拒绝。
- `public-lottery-screens`：对外四屏展示与主持人切屏控制。
- `hard-preset-draw`：按奖品硬内定中奖人；开奖必中内定者；不可重复中奖。
- `local-lottery-api`：Express API + JSON 文件读写配置、用户、内定与结果。

### 修改能力

- （无：空仓库，无既有 approved behavior）

## 范围（Scope）

### 范围内（In Scope）

- 多奖次列表与当前奖品切换
- 假二维码参与页 + 添加用户
- 抽奖滚动与中奖展示
- `/admin` 隐藏路由 + 本地口令
- 硬内定、不可重复中奖、重名校验
- 主持人控制条（可隐藏）
- 轻量动效（无音效/粒子）

### 范围外（Out of Scope）

- 真实扫码、微信/OAuth 登录
- 一奖多名、云端多租户、强安全鉴权
- 音效、背景音乐、粒子/烟花、主题皮肤
- Git worktree 隔离（本机暂无 Git）

## 影响（Impact）

- 影响的代码区域：新建应用根目录（如 `apps/lottery/` 或仓库根下 `client/` + `server/`）、本地数据目录（如 `data/`）
- 影响的 API 或接口：新增 REST 风格本地 API（奖品、用户、内定、开奖、会话状态）
- 依赖或涉及的外部系统：无（仅本机 Node 运行时与浏览器）
